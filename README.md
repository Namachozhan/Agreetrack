# AgriTrack — OpenShift-ready MVP

AgriTrack is a starter tractor and agricultural-equipment rental management application.

## Stack
- Frontend: React + Vite, served by unprivileged Nginx
- Backend: Python + FastAPI + SQLAlchemy
- Database: PostgreSQL
- Platform: OpenShift BuildConfig, ImageStreams, Deployments, Services, PVC and Route

## MVP features
- Dashboard totals and rental status overview
- Equipment register (tractor / implement / other)
- Customer register
- Rental creation with hourly, daily or per-acre pricing
- Rental list and status updates
- PostgreSQL persistence

This is an MVP starter, not a production-hardened multi-tenant SaaS. Authentication, authorization, audit logging, payment integration, backups, monitoring and tenant isolation must be implemented before real customer/business use. Do not expose it publicly with sensitive customer data until authentication is added.

## 1. Push to GitHub
Create an empty GitHub repository, then from this folder:
```bash
git init
git add .
git commit -m "Initial AgriTrack application"
git branch -M main
git remote add origin https://github.com/YOUR_GITHUB_USERNAME/YOUR_REPOSITORY.git
git push -u origin main
```

## 2. Create an OpenShift project
```bash
oc login https://api.YOUR-CLUSTER:6443
oc new-project agritrack
```

## 3. Create a GitHub PAT secret
Create a GitHub fine-grained PAT with **read-only Contents access** to this repository. Do not put the token in Git or in a committed YAML file.

For a private repository:
```bash
oc create secret generic github-pat \
  --type=kubernetes.io/basic-auth \
  --from-literal=username=YOUR_GITHUB_USERNAME \
  --from-literal=password=YOUR_GITHUB_PAT
```

For a public repository, the Git secret is not required. Remove `sourceSecret` from both BuildConfigs in `openshift/02-buildconfigs.yaml`.

## 4. Update the repository URL
Edit `openshift/02-buildconfigs.yaml` and replace:
`https://github.com/YOUR_GITHUB_USERNAME/YOUR_REPOSITORY.git`
with your actual GitHub repository URL.

## 5. Create database secrets
Choose one long random **alphanumeric** password and use the same value in both commands:
```bash
oc create secret generic agritrack-db \
  --from-literal=POSTGRESQL_USER=agritrack \
  --from-literal=POSTGRESQL_PASSWORD=REPLACE_WITH_LONG_RANDOM_ALPHANUMERIC_PASSWORD \
  --from-literal=POSTGRESQL_DATABASE=agritrack

oc create secret generic agritrack-backend \
  --from-literal=DATABASE_URL='postgresql+psycopg://agritrack:REPLACE_WITH_LONG_RANDOM_ALPHANUMERIC_PASSWORD@agritrack-postgres:5432/agritrack'
```
The password is intentionally created as a cluster Secret rather than stored in YAML/Git.

## 6. Deploy database, builds, app and Route
Apply in this order:
```bash
oc apply -f openshift/01-database.yaml
oc apply -f openshift/02-buildconfigs.yaml
oc apply -f openshift/03-app.yaml
```

Start the first builds:
```bash
oc start-build agritrack-backend
oc start-build agritrack-frontend
```

Watch:
```bash
oc get builds -w
oc get pods -w
```

Get the public URL:
```bash
oc get route agritrack
```

Open the `HOST/URL` shown by the Route. The frontend proxies `/api` requests to the backend Service.

## 7. Updating the application
After pushing code to GitHub:
```bash
oc start-build agritrack-backend
oc start-build agritrack-frontend
```
The BuildConfigs create new ImageStream tags. OpenShift image-change triggers update the Deployments.

To enable automatic builds on every GitHub push, configure a GitHub webhook for each BuildConfig using the webhook URL generated by:
```bash
oc describe bc agritrack-backend
oc describe bc agritrack-frontend
```
Treat webhook URLs as secrets. Do not publish them.

## 8. Useful troubleshooting commands
```bash
oc get pods,svc,route,bc,is,pvc
oc describe pod POD_NAME
oc logs deployment/agritrack-backend
oc logs deployment/agritrack-frontend
oc logs deployment/agritrack-postgres
oc get endpoints

```

## Notes
- The manifests use standard Kubernetes `Deployment` objects, not deprecated OpenShift `DeploymentConfig`.
- `BuildConfig` is used for OpenShift-native Dockerfile builds.
- The GitHub PAT is only used by the build system to clone a private repository. It is not passed to the running application.
- The PostgreSQL password is stored in an OpenShift Secret. Replace the example value before deployment.
- The PostgreSQL image is from the CentOS Stream SCLorg collection and is designed for OpenShift-style arbitrary UID execution. Confirm your cluster can pull it.
- The app currently creates database tables on startup for convenience. For production, use Alembic migrations.
